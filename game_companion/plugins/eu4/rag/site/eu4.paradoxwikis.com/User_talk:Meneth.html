      Merged template: Group idea[edit source]

      As per the discussion on the national ideas talk page, I went ahead and merged the individual idea group subtemplates into one Group idea template. I still prefer to have them listed on the National ideas page and transcluded from there though. I'm not sure if this is what you had in mind for the merged template so let me know if anything needs changing. Haven't made any other changes yet. If everything is ok, I'll start replacing all the NIs on the region and country pages after the region pages are all done. ~ SolSys (talk) 00:36, 3 January 2016 (CET)

      Looks good. The main reason to prefer templates over section transclusion is that templates are native to MediaWiki, and thus almost certainly better optimized than the section transclusions are. ~ Meneth (talk) 00:48, 3 January 2016 (CET)

      Yes, it is what I mean. Just think about it before do an edit like this. Stigni (talk) 14:17, 3 January 2016 (CET)
      I don't think it will be a problem. The only place they are [and plan to be] used is on the regions and country pages [as far as I'm aware of]. I do have some future plans, but hopefully it won't be an issue. ~ SolSys (talk) 12:25, 3 January 2016 (CET)

      Formation Decision[edit source]

      I thought that it could be useful to have all (Re)Formation decision in one page, and have a transclusion them in each single country page; so it could more easy to update and the user could see all country decisions all together. For that I start insert all decision in my sandbox. What do you think? Stigni (talk) 11:13, 5 January 2016 (CET)

      I'm not certain we need this, the reason that we want to use transclusions is to prevent duplication and missed updates. Now all of the formation decisions can be trascluded (I set that up yesterday) the remaining advantage is in updating the pages. However we've already got methods for knowing if something needs updating in the inbuilt sversion tags. There is an argument to be made for a (re)formations page but I'm not convinced by it yet. Dauth (talk) 11:26, 5 January 2016 (CET)
      Dauth's argument seems pretty solid. Got any further arguments, Stigni? ~ Meneth (talk) 12:35, 5 January 2016 (CET)
      The main reason I can think of for this page [updating aside] is that many nations can form some nations, so it would be easier to transclude them from a single source instead of a different page for each formation. Maybe combine it with the current Formable countries page. ~ SolSys (talk) 13:34, 5 January 2016 (CET)
      We have a page with all the decision and for example Cultural Shift that is transclusion in Culture or Institute the Societas Jesu that is transclusion in Portugal/Spain. So for the sake of completeness we don't remove this two decision from Decisions page. With the same idea we need to create a page with all (or spitted by superregion) formation decision; also because the custom nation could form new nation and have in one page the list of the requirements and of the effects it could be very usefull to decide the culture of the CN. Stigni (talk) 16:13, 5 January 2016 (CET)
      At the moment the decision is on the country page of the nation build which is formed. I think this is a good choice. All infoboxes have a versioning. It's not necessary to update them at once. I don't see an advantage in a collection of all formation decisions on a page.
      Referring to the previous section of this talk page I could think to put all decisions/events/missions which are used on several pages (transcluded) in (sub)templates, e.g. for the formation of Egypt: {{decision/Form Egypt}}. (With only collapse as optional parameter.) – Lillebror (talk) 18:59, 5 January 2016 (CET)

      Template:Country protection option[edit source]

      Template:Country is protected with the "cascading" option turned on, so it protect all pages that are transcluded in it. This include Template:National ideas/defg. So we can not edit it. Stigni (talk) 08:49, 8 January 2016 (CET)

      As 'halfop' you are allowed to edit it. – Lillebror (talk) 09:26, 8 January 2016 (CET)
      But I can't: "You do not have permission to edit this page". Stigni (talk) 09:55, 8 January 2016 (CET)
      Idk why you couldn't edit it. (Edit: You are right.) I think it's a good idea that these pages could be edited by more users, so I removed the cascading protection of the country template. – Lillebror (talk) 10:44, 8 January 2016 (CET)
      Fine by me. Admins (halfop+) only should be plenty. ~ Meneth (talk) 11:45, 8 January 2016 (CET)

      Labelled section transclusion[edit source]

      I just added a section to Decisions#Tribal so I could add the "Reform the Government" decision to Timurids. So why doesn't transcluding it work? Here's a test:

      It works in my sandbox so I have no idea what I'm doing wrong. Hairy Dude (talk) 03:20, 11 January 2016 (CET)

      Everything. ;-D
      A labelled section transclusion doesn't work inside template parameter, in your case of the {{box wrapper}} template. You have to substitute the template. – Lillebror (talk) 07:16, 11 January 2016 (CET)
      Heh. Thanks. Hairy Dude (talk) 17:50, 11 January 2016 (CET)
      Perhaps you could make a version of {{box wrapper}} that is transclusion-friendly? Call them {{template|box wrapper begin}} and {{template|box wrapper end}}, for example. That way the contents won't be inside a template. Would that work? Hairy Dude (talk) 17:52, 11 January 2016 (CET)
      If you have to change the box wrapper to the code you can simply substitute it with {{subst:Box wrapper}}. Stigni (talk) 18:25, 11 January 2016 (CET)
      It would make things more fluid and more standardized for sure [especially shortened {{template|bw_s}} and {{template|bw_e}}]. I just feel silly when {{template|bw_e}} is actually only </div>. ~ SolSys (talk) 18:32, 11 January 2016 (CET)
      Good idea, Hairy Dude.
      I have changed the template for an additional alternative syntax: {{box wrapper}} boxes {{end box wrapper}}. The original syntax is still valid: {{box wrapper| boxes }}. – Lillebror (talk) 20:03, 11 January 2016 (CET)
      But a substitution of the box wrapper template produces now a long code because of the #if clause. I undo my changes. Perhaps its better to create two alternative template. (In this case I prefer a not abbreviated name.) – Lillebror (talk) 20:18, 11 January 2016 (CET)
      You just need a safesubst token in there. I've reverted your revert, and added it. Substituting will now resolve the #if, making it nice and small. ~ Meneth (talk) 20:21, 11 January 2016 (CET)

      Talk Pages[edit source]

      In the past, I've been updating the talk pages on articles I edit with a summary of what I have changed. Should I stop this and only edit a talk Page when I have related questions?, For example, if I need more information on certain back-end game mechancics related to the page, but don't know where to find them?

      Also, on pages tagged with "Rewrite", should I remove the rewrite commentary on the talk page once I feel it's complete, or simply leave commentary as I have done in the past?

      Cragspyder (talk) 21:12, 8 April 2016 (CEST)

      Usually, it is possible to sum up what you've done in the actual edit summary. In those cases, you should do so.
      Only if you've changed too much to reasonably sum it up there is there much need to edit the talk page.
      It is mostly meant for when people are unsure about how it'd be best to do something, or the facts of the matter.
      You should remove the rewrite tag when you feel it is done, yes. Make sure to use the word "rewrite" in your edit summary when you do so, so that it is easily spotted. ~ Meneth (talk) 21:16, 8 April 2016 (CEST)
      Sorry, I have already been removing the Rewrite tag itself from the main article once complete; What I meant was, should I remove the list of Rewrite requirements (on the talk page) as well?. Cragspyder (talk) 21:21, 8 April 2016 (CEST)
      I don't think that's needed, no. Maybe add strikethrough and comment that you've addressed the complaints. ~ Meneth (talk) 21:28, 8 April 2016 (CEST)

      Usage of Template:Mission_tree on an external wiki and what plugins are needed, if any[edit source]

      Hello there. Would it be allowable for a mod's wiki to use Template:Mission_tree and Template:Mpos for their own mod's mission trees, and if so what plugins are required to be installed on the server? 157.52.108.35 20:39, 29 April 2019 (UTC)

      Hi there, Meneth has moved to other projects inside PDX. You may use the templates for your mod, though if you wish you could also host it on this wiki (mod will need to follow common wiki rules). Be advised that you will need ImageMap installed, but IIRC it should be bundled with the latest MW release. Note: to clarify, the permission is only for the templates, I cannot respond on the use of PDX assets outside of the PDX wikis. ~ SolSys (talk) 09:28, 30 April 2019 (UTC)
